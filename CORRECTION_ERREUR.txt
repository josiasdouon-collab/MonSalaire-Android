MON SALAIRE V6 WINDOWS - CORRECTION

Erreur corrigée :
TypeError: argument should be a str or an os.PathLike object where __fspath__ returned non-str

Cause : main.py utilisait App.user_data_dir au niveau global avant la création de l'instance Kivy.

Correction : le chemin de la base SQLite est maintenant construit dans DBMixin.init_db() à partir de self.user_data_dir, une fois l'application Kivy démarrée.

Pour reconstruire :
1. Ouvrir ce dossier dans Visual Studio Code.
2. Ouvrir un terminal.
3. Double-cliquer sur CREER_EXE.bat ou lancer .\\CREER_EXE.bat.
4. L'EXE se trouve dans dist\\MON SALAIRE\\MON SALAIRE.exe


--- CORRECTIONS COMPLEMENTAIRES (V6 corrige 2) ---

1. Plantage au demarrage (KV invalide)
   Les 3 cartes colorees de l'accueil utilisaient "Color: rgba: ..." et
   "RoundedRectangle: pos: ...; size: ..." sur une seule ligne, ce que Kivy refuse
   ("Invalid data after declaration"). Ecrit maintenant sur plusieurs lignes.

2. Bouton "Reessayer" inoperant
   Les ecrans etaient ajoutes seulement si la base s'ouvrait dans build().
   Les ecrans sont maintenant toujours charges ; la base est ouverte une seule fois
   dans startup(), donc "Reessayer" fonctionne vraiment.

3. Base de donnees ouverte deux fois
   init_db() est maintenant repetable : l'ancienne connexion est fermee avant d'en
   ouvrir une nouvelle.

4. Totaux "Scolarite / prets" effaces
   Dans CommitmentsScreen.refresh(), une seconde affectation ecrasait le texte et
   supprimait "Total mensualites prets", "Provision scolarite mensuelle" et
   "Engagements mensuels". Cette seconde affectation est supprimee.

Test : application demarree en mode sans ecran, les 8 ecrans s'ouvrent sans erreur ;
Reste = salaire - depenses - engagements verifie (300 000 - 15 000 = 285 000 F).

--- NOUVEAUTE (V6 corrige 7) : MENUS EPARGNE ET OBJECTIFS ---

Les boutons Epargne et Objectifs de l'accueil ouvraient le meme ecran que Budget.
Chacun a maintenant son propre menu :

   priorite (Urgente / Normale / Secondaire).
 - Tableau : objectifs actifs, montant total, echeance la plus proche, taux de realisation.
 - Chaque objectif : montant reuni, reste a financer, barre de progression, mois restants,
   date previsionnelle d'atteinte et conseil d'epargne mensuelle.
 - Modifier / supprimer (l'argent epargne passe en "Epargne libre", rien n'est perdu).

LIEN ENTRE LES DEUX : chaque versement enregistre dans Epargne met a jour
automatiquement la progression de l'objectif correspondant (pas de double comptage).

Les donnees existantes sont conservees : deux nouvelles tables sont ajoutees a la base.
Android : la touche Retour du telephone revient a l'ecran precedent.


--- CORRECTION (V6 corrige 8) : "no such column: g.note" a l'ouverture de Epargne ---

Cause : la base de donnees de l'utilisateur contenait deja une ancienne table "goals"
(version precedente) avec d'autres colonnes ; la nouvelle table n'etait donc pas creee.
Correction : au demarrage, si une ancienne table "goals" ou "savings" est incompatible,
elle est conservee sous un autre nom (ex. goals_ancien_AAAAMMJJHHMMSS) et la nouvelle
table est creee. Aucune donnee n'est supprimee.
